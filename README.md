## Complexity and design notes

- **Q1:** Repeated String concatenation in a loop can copy an increasing amount of text (quadratic total copying in the number of fields). StringBuilder appends to a mutable buffer and is generally linear in output size. StringBuffer synchronizes its methods; use a local StringBuilder for an individual ticket and a synchronized/thread-safe design for a shared log.
- **Q2:** ArrayList has O(1) indexed access and amortized O(1) append, but O(n) front/middle insertion and removal. LinkedList has O(1) insertion/removal once positioned but O(n) traversal to reach an index. ArrayDeque is suitable for both-end queue operations and has no indexed access.
- **Q3:** Equal objects must return the same hash code. Student.hashCode() uses regNo, the same field used by equals(). Do not mutate equality/hash fields while an object is in a hash collection.
- **Q4:** HashMap has average O(1) lookup without ordering; TreeMap maintains sorted keys with O(log n) lookup; LinkedHashMap preserves insertion order with average O(1) lookup. Other report orders require sorting or separate insertion-order information.
- **Q5:** The comparator orders points descending, goal difference descending, and name ascending. The generic leaderboard sorts a copy, leaving its stored list unchanged.
- **Q6:** PriorityQueue insertion and removal are O(log n). The arrival counter makes equal-severity patients FIFO. A real deployment needs a clinically approved waiting-time escalation policy to reduce starvation.
- **Q7:** StringBuilder avoids repeatedly creating intermediate immutable strings. The benchmark checks that both implementations produce identical output before timing.
